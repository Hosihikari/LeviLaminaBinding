# Hosihikari.Bindings.LeviLamina

[English](README.md) | [简体中文](README.zh_hans.md)

The LeviLamina LLAPI capability surface for the Hosihikari projection: a CI-generated native-style **Interop**, a hand-written .NET **Idiomatic** layer, and the native **binding shim**.

## Boundary

- `Hosihikari.Bindings.LeviLamina.Interop` is generated by `Hosihikari/BindingGenerator` from the versioned IR. It mirrors LLAPI declarations: single-level pointer and reference returns become typed borrowed wrappers, `optional_ref<T>` results reuse those wrappers, and other opaque handles stay `nint`; it is committed and checked by a CI regeneration diff.
- `Hosihikari.Bindings.LeviLamina` is the hand-written .NET layer: properties, events, operators, indexers, constructors, and the service-thread scheduler. It is not generated.
- `native/BindingShim/` is the C ABI projection compiled with LeviLamina's xmake/LLVM toolchain. It does not host the CLR; the HostingShim is a separate layer.

## Current state

The Interop and Idiomatic projects build. The carrier-linked generated Interop, the v1 绑定垫片 table with its `extern "C"` implementations, and the coverage manifest are committed:

- `src/Hosihikari.Bindings.LeviLamina.Interop/Generated/` contains the generated native-style C# classes and `NativeMethods`; deliberately unsupported members are `NotSupportedException` stubs marked `[Obsolete]`, so calls raise compiler warning CS0618.
- `native/BindingShim/generated/win-x64-server/levilamina/` contains the 3,819-function table and its implementations.
- `coverage/` contains the coverage manifest, summary, baseline, and provenance.

The host calls `Hosihikari.Bindings.LeviLamina.Interop.NativeMethods.Load(path)` before using a generated wrapper. `native/BindingShim/build.ps1` builds the shim with clang-cl against `LeviLamina.lib`, fmt, and prelinked Bedrock imports.

## Generated-source gate

`scripts/verify_generated.py` checks provenance, the coverage baseline, the native table function count, the table version, and the managed table. The CI builds the solution, runs this verifier, and validates the committed coverage contract with the generator.

Regenerate after a new IR:

```shell
powershell -File scripts/regenerate.ps1 -IrDirectory ..\Bindings.Generator\artifacts\llapi-full-ir -AbiRoot ..\Bindings.Abi
```

## Runtime smoke

`scripts/run-runtime-smoke.ps1` builds the shim and Interop, installs a C# test plugin into a local BDS + LeviLamina server, and verifies the result file. It requires Windows x64, BDS 1.26.51.1, LeviLamina 26.51.7, the Hosihikari host, and `hosihikari-csharp`:

```shell
powershell -File scripts/run-runtime-smoke.ps1 -ServerRoot C:\path\to\bedrock-server
```

The plugin validates `NativeMethods.Load`, `EventId`, `Version`, out-of-line `ll::Error` construction/`message()`/destruction, allocator-backed virtual-destructor lifecycles, `std::function` callback invocation/release, and the native-exception boundary. The expected output and requirements are in `tests/runtime-smoke/README.md`.

## Benchmarks

`scripts/run-benchmarks.ps1` loads the shim in the same BDS process and reports nanoseconds and managed allocation per call for field getters, scalar methods, string parameters/results, shared handles, and vector parameters. It writes `data/hosihikari/shim-benchmarks/benchmarks.txt`; the numbers are environment-dependent and are not a CI gate. See `tests/benchmarks/README.md`.

## Build

```shell
dotnet build Hosihikari.Bindings.LeviLamina.slnx -c Release
```

The package version follows the upstream version plus the binding revision (`26.51.7-r0`). The platform for this surface is Windows x64.
